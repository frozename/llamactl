record captures the P6 footprint measurements behind retiring the Electron
shell in favor of the already-shipped web console
(`packages/app/src/main.web.tsx`, built by
`bun run --cwd packages/app build:web`).

Reading the numbers:

- **Renderer retention.** Only `renderer.retainedLines` of `renderer.totalLines`
  lines in `packages/app/src` are reachable from `main.web.tsx` — the web entry
  already carries the console. The issue baseline was 26015 lines; the retained
  web surface is well under it.
- **Lockfile.** Removing the seven removable deps from `packages/app` drops a
  large transitive closure of `lockfile.delta.totalEntries` (`removed` entries
  unreachable afterwards; the added `@playwright/test` closure is small).
- **CI cost.** `ci.electronUiTotal.wallClockMinutes` is approximate wall clock,
  **not billable** minutes: the three Electron UI workflows run on
  `macos-latest` runners whose billing multiplier is materially higher than the
  `ubuntu-latest` `console-e2e` path, so the raw figure understates the
  Electron path's cost. This is a CI-cost caveat only — the bench scheduler
  mentioned in Known gaps is an Electron-only product capability (the
  `models.bench` schedule loop), not a CI-minute normalization facility.

## Known gaps

- The **bench scheduler** — the `models.bench` schedule CRUD and the loop
  start/stop/kick/status controls — still lives in Electron main's memory.
  Its disposition is recorded: keep scheduled benches, and move the loop and
  CRUD to the `llamactl bench schedule` CLI with an opt-in long-lived host.
  The move has not landed yet; it is P7-A precondition (b) and is in flight
  (separate PR).
- The Electron UI workflows still reference `electron-mcp` (`electronMcp.
referencingWorkflows`); the `console-e2e` path has zero such references.
- There is **no live usage study** quantifying which Electron-only affordances
  operators rely on day to day.
- There is no `llamactl console` launcher yet (`setup.console.launcherPresent`
  is false); it is in flight as a separate PR.
- Pipeline drafts and chat history live in localStorage only: operators must
  export that state before Electron retires — there is no auto-migration.
- `console-e2e` needs ≥ 5 consecutive green runs on main before P7-A entry
  (precondition (d)).

## Risks

- Task coverage here is a static needle grep over spec text: a spec skipped at
  runtime would still read as covered. The `console-e2e` workflow actually
  executing the specs (precondition (d)) is the execution guard.
- localStorage-only state (pipeline drafts, chat history) is lost if operators
  do not export it before Electron retires; there is no auto-migration.
- If Electron is removed before precondition (b) lands, scheduled benches
  lapse; the rejected alternative was to accept "scheduled benches stop" as an
  explicit loss — the recorded decision keeps scheduled benches instead.
- There is no live usage study, so the T1–T6 list stands in for real usage;
  an Electron-only affordance that none of the tasks models could be missed
  entirely by this record.
- The macOS CI multiplier means the Electron path's true cost is understated by
  raw `wallClockMinutes` — deciding on the raw numbers alone could either
  over- or under-value the migration savings.
- Ad-hoc signing (`signing.identity: "-"`) is fine for a local launcher but is
  a separate distribution question from the runtime choice; do not conflate.

## Recommendation

**Option A — focused web conversion.** The corrected measurements show the web
console carries the operator surface: T1 through T6 are all covered by the
real Playwright specs (T2, T5 and T6 since the #500 assertions). Renderer
retention is small, the `console-e2e` path has zero `electron-mcp`
references, `build:web` is present and there is no signing gate — on top of a
large dependency cut. The plan offers exactly two options: **Option A —
focused web conversion** (P7-A: remove Electron and ship the web console as
the primary surface), and **Option B — retire the UI completely** (P7-B: the
CLI/MCP-only fallback product). The operator decision recorded below confirmed
this lean: Option A. `T1-T5-no-cli-fallback` now passes;
`setup-le-3-no-signing` still fails only because the `llamactl console`
launcher is missing. The honest caveat from the plan stands separately: there
is no live usage study, so the T1–T6 list stands in for real usage; if a
future usage study surfaces Electron-only affordances with no web equivalent,
flip to Option B and retire the UI completely to the CLI/MCP product.

## Operator decision

Decision: **Option A — focused web conversion (P7-A)**, recorded on #410 on
2026-11-07. The operator's words: "A. for 2 do as you recommend".

Bench scheduler disposition: keep scheduled benches — scheduled benches do not
stop. The loop and CRUD move behind a `llamactl bench schedule` CLI
(list/add/rm/toggle plus loop start/stop/kick/status), with an opt-in,
explicitly started long-lived host.

Remaining P7-A entry preconditions:

- (b) the bench scheduler move (in flight, separate PR);
- (c) operators export localStorage-only state (pipeline drafts, chat
  history);
- (d) `console-e2e` green on main for ≥ 5 consecutive runs;
- the `llamactl console` launcher (in flight, separate PR).

Electron deletion starts only once all of these are met.
