# Decision record #410 — UI runtime: Electron vs browser console

Status: **P7-A complete — merged in #514; #410 is closed. Electron is
removed and the Bun-served web console is the only UI runtime.** This
record captures the P6 footprint measurements
behind retiring the Electron shell in favor of the already-shipped web
console (`packages/app/src/main.web.tsx`, built by
`bun run --cwd packages/app build:web`), plus the post-deletion
re-measurement below. Both runs used `MEASURE_410_OFFLINE=1` (`gh` was
unavailable), so `ci.value` is null in the committed JSON; the CI figures
quoted in prose come from the earlier online P6 run embedded in git
history.

Reading the numbers (post-P7-A tree):

- **Renderer retention.** `renderer.retainedLines` is unchanged at 3278 —
  the web entry already carried the whole console — but `renderer.totalLines`
  dropped from 29239 to 4578 once the retired modules, shell, stores and
  Electron renderer sources were deleted, so `renderer.ratio` reads 0.716.
  The ratio is a share-of-remaining-source metric, not a growth signal.
- **Dependencies.** `dependencies.removablePresent` is 0 of 7: electron,
  electron-builder, electron-vite, electron-trpc, undici, bufferutil and
  utf-8-validate are gone from `packages/app/package.json`. The one added
  dependency remains `@playwright/test`.
- **Electron tree.** `electron.count` is 0 and `electron.files` is empty;
  `electronMcp.referencingWorkflows` is empty now that the three macOS UI
  workflows are deleted.
- **Shims.** `shims.absent` lists the two measured shim files
  (`electron.vite.config.ts`, `electron/trpc/dispatcher.ts`) and every
  shim counter is 0 — the Bun/undici shims, the v10 compatibility symbols
  and the workspace bundle entries left with the Electron runtime.
- **Lockfile.** `bun.lock` shrank with the deletions; `lockfile.delta`
  now models zero further removable entries (`removed: 0`).
- **CI cost.** The `ci` block is offline in this run (`offline: true`,
  `value: null`); the P6 online run recorded `electronUiTotal` at ~2906
  wall-clock minutes per 30 days across the three deleted macOS workflows
  plus ~103 for `console-e2e` — see Measured before/after below.

## Risks

- Task coverage here is a static needle grep over spec text: a spec skipped
  at runtime would still read as covered. `console-e2e` actually executing
  the specs on every PR and push to main is the execution guard.
- The web console is now the only UI: a console-server outage leaves
  operators with the CLI/MCP surface only. The lifecycle costs this
  implies are listed under Remaining costs.
- There is no live usage study, so the T1–T6 list stood in for real usage;
  an Electron-only affordance that none of the tasks modeled could have
  been missed entirely by this record.

## Remaining costs

The web console is not free; these are the costs P7-A keeps on the books:

- **Browser transport.** tRPC `httpBatchLink` + `httpSubscriptionLink`
  (SSE) links in `packages/app/src/lib/transport/http.ts`, plus the
  reconnect wrapper in `sse-lifecycle.ts` that re-establishes dropped
  streams with backoff and replays the invalid-session path.
- **Console server lifecycle.** `llamactl console` is started manually,
  the operator picks the port, and a restart invalidates every session —
  there is no always-on daemon yet.
- **Auth layer.** The port-scoped session cookie/nonce, Host/Origin/
  Sec-Fetch-Site guards, plus the allowlist, per-procedure projection and
  sentinel upkeep in `@llamactl/remote`'s console server whenever an
  exposed procedure changes.
- **Playwright/Chromium.** `@playwright/test` is a devDependency of
  `packages/app` and CI downloads the chromium build on every
  `console-e2e` run — cheaper than macOS minutes, not free.
- **Dispatch module.** `@llamactl/remote`'s `dispatch/router.ts` remains
  the host-agnostic local-vs-pinned-remote layer the console server
  wraps; it is shared infrastructure, not Electron residue.

## Recommendation

**Option A — focused web conversion.** The corrected measurements showed
the web console carries the operator surface: T1 through T6 are all
covered by the real Playwright specs (T2, T5 and T6 since the #500
assertions). Renderer retention was small, the `console-e2e` path had zero
`electron-mcp` references, `build:web` was present and there was no
signing gate — on top of a large dependency cut. The plan offered exactly
two options: **Option A — focused web conversion** (P7-A: remove Electron
and ship the web console as the primary surface), and **Option B —
retire the UI completely** (P7-B: the CLI/MCP-only fallback product). The
operator decision recorded below confirmed this lean: Option A, and P7-A
has now executed — Electron is removed and the measured before/after is
above. `T1-T5-no-cli-fallback` passes and `setup-le-3-no-signing` passes
with the `llamactl console` launcher shipped. The honest caveat from the
plan stands separately: there was no live usage study, so the T1–T6 list
stood in for real usage; had a usage study surfaced Electron-only
affordances with no web equivalent, the fallback was Option B — retire
the UI completely to the CLI/MCP product.

## Operator decision

Decision: **Option A — focused web conversion (P7-A)**, recorded on #410
on 2026-11-07. The operator's words: "A. for 2 do as you recommend".

Bench scheduler disposition: keep scheduled benches — scheduled benches do not
stop. The rejected alternative, accepting "scheduled benches stop" as an
explicit loss, was not taken. The loop and CRUD moved behind a
`llamactl bench schedule` CLI (list/add/rm/toggle plus loop
start/stop/kick/status), with an opt-in, explicitly started long-lived host.

P7-A entry preconditions, all met before deletion:

- (b) the bench scheduler move (`llamactl bench schedule`);
- (c) localStorage-only state — the operator confirmed on 2026-11-07 that
  there is no localStorage state to keep;
- (d) `console-e2e` green on main for ≥ 5 consecutive runs;
- the `llamactl console` launcher.

Electron deletion has landed: `packages/app/electron/**`, the packaging
configs, the IPC transport and the retired renderer modules are gone, the
console manifest ships exactly `fleet`, `workloads`, `nodes` and `logs`,
and `console-e2e` is the required UI check. #369 closed as superseded once
the post-merge green streak existed.
