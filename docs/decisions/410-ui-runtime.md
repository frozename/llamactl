`## Operator decision` line stays blank until a human picks Option A or B.

Reading the numbers:

- **Renderer retention.** Only `renderer.retainedLines` of `renderer.totalLines`
  lines in `packages/app/src` are reachable from `main.web.tsx` — the web entry
  already carries the console. The issue baseline was 26015 lines; the retained
  web surface is well under it.
- **Lockfile.** Removing the seven removable deps from `packages/app` drops a
  large transitive closure of `lockfile.delta.totalEntries` (`removed` entries
  unreachable afterwards; the added `@playwright/test` closure is small).
- **CI cost.** `ci.electronUiTotal.wallClockMinutes` is approximate wall clock,
  **not billable** minutes: the three Electron UI workflows run on
  `macos-latest` runners whose billing multiplier is materially higher than the
  `ubuntu-latest` `console-e2e` path, so the raw figure understates the
  Electron path's cost. This is a CI-cost caveat only — the bench scheduler
  mentioned in Known gaps is an Electron-only product capability (the
  `models.bench` schedule loop), not a CI-minute normalization facility.

## Known gaps

- The **bench scheduler** — the `models.bench` schedule CRUD and the loop
  start/stop/kick/status controls — is Electron-only: the loop lives in
  Electron main's memory. Its disposition is precondition (b) for P7-A and
  P7-B requires it too: either move the loop and CRUD to the agent or the
  console with a `llamactl bench schedule` CLI, or accept "scheduled benches
  stop" as an explicit loss. **P7 is blocked** until the operator records that
  disposition; removing Electron otherwise silently ends scheduled benches.
- There is no dedicated credentials spec at
  `packages/app/e2e/credentials.spec.ts` (a no-credentials-in-browser sweep
  over HAR, DOM and storage); `securityChecklist.credentialsSpec` stays
  `false` until it lands.
- The Electron UI workflows still reference `electron-mcp` (`electronMcp.
referencingWorkflows`); the `console-e2e` path has zero such references.
- There is **no live usage study** quantifying which Electron-only affordances
  operators rely on day to day.
- One console e2e case is parked behind `test.fixme` in
  `packages/app/e2e/logs.spec.ts` (a dropped stream reconnecting into a fresh
  tail behind a divider). It must be un-fixed before the web console can be
  called parity-complete with Electron.

## Risks

- Retiring Electron before T5 (two concurrent tabs) and T6 (recover after a
  console restart) are covered risks a regression with no automated guard.
- There is no live usage study, so the T1–T6 list stands in for real usage;
  an Electron-only affordance that none of the tasks models could be missed
  entirely by this record.
- The macOS CI multiplier means the Electron path's true cost is understated by
  raw `wallClockMinutes` — deciding on the raw numbers alone could either
  over- or under-value the migration savings.
- Ad-hoc signing (`signing.identity: "-"`) is fine for a local launcher but is
  a separate distribution question from the runtime choice; do not conflate.

## Recommendation

**Provisional — leans Option A, pending T2/T5/T6 coverage and the bench
scheduler disposition.** The corrected measurements show the web console mostly
carries the operator surface: T1 (find the unreachable node), T3 (tail X's logs
on a remote node) and T4 (stop X with confirmation) are covered by the real
Playwright specs; T2 (find workload X's phase and endpoint) is only **partial**
— the endpoint is asserted in `fleet.spec.ts`, no spec asserts a phase.
Renderer retention is small, the `console-e2e` path has zero `electron-mcp`
references, `build:web` is present and there is no signing gate — on top of a
large dependency cut. The plan offers exactly two options: **Option A — focused
web conversion** (P7-A: remove Electron and ship the web console as the primary
surface), and **Option B — retire the UI completely** (P7-B: the CLI/MCP-only
fallback product). The evidence above leans Option A. This is explicitly a lean,
not a decision: `net-deps-removed-gt-added`, `renderer-le-25pct` and
`zero-electron-mcp` pass, but `T1-T5-no-cli-fallback` and
`setup-le-3-no-signing` do **not** — full T2 coverage (a spec asserting a
workload phase), T5 coverage, T6 coverage (recover after a console restart) and
a `llamactl console` launcher must land first, and the bench scheduler
disposition (P7-A precondition (b); P7-B needs it too) must be recorded. The
honest caveat from the plan stands separately: there is no live usage study, so
the T1–T6 list stands in for real usage; if a future usage study — not T6,
which only measures restart recovery — surfaces Electron-only affordances with
no web equivalent, flip to Option B and retire the UI completely to the CLI/MCP
product.
